# 2.1 — Logo and favicon

**Status:** Done
**Branch:** `feat/2.1-logo-favicon`
**Plan reference:** RMT_Website_Plan.docx, task 2.1 (step: "Create or commission a simple
logo/wordmark and a matching favicon (replace the default favicon.png)"). This is the last open step of 2.1.

## Goal

Visitors see the Kinetic Flow brand mark next to the business name in the site's navigation, and in
the browser tab, bookmarks, and an iPhone home-screen shortcut, instead of Blazor's purple "@" icon.
The mark looks sharp on every screen and works on light and dark browser themes.

## Current state

- `wwwroot/favicon.png` is the default Blazor template icon (purple "@", 32×32, 1 KB), linked from
  `Components/App.razor:17` as `<link rel="icon" type="image/png" href="favicon.png" />`.
- There's no `favicon.ico`. Browsers that read the `<link rel="icon">` don't need it, but search
  crawlers, RSS readers, link previews, and some older browsers request `/favicon.ico` directly,
  whatever the HTML says, and get a **404** today.
- No `apple-touch-icon`, so an iPhone "Add to Home Screen" shows a blurry screenshot of the page.
- The brand appears as text only: `NavMenu.razor:3` (`Kinetic Flow RMT`, the sidebar's top bar) and
  `MainLayout.razor:11` (the full name, header).
- **The T-shirt in `profilePic.jpg` already has a printed "KINETIC FLO…" logo with a mark.**
  If a file for that logo exists, it should be the starting point (see Open questions).

### Overlap with 2.3

2.3 replaces the sidebar with a top navbar, "logo/brand on the left". To avoid redoing work, the
logo is built as its own small component (`BrandLogo.razor`). This PR puts it in today's
`NavMenu`, and 2.3 just moves the one tag.

## Approach

### 1. Where the design comes from (decision needed)

| Option | What it means | Trade-off |
|---|---|---|
| **A. Existing logo** (recommended if it exists) | You provide the logo file from the T-shirt printer or designer, ideally **SVG, AI, EPS, or PDF**. A PNG of at least 512px works too. | The site matches the real-world brand. Needs a file from you. |
| **B. Simple mark built here** | A plain SVG mark in the brand colours, e.g. a "KF" monogram or a flowing wave, plus the name as text in Lora. | Can be done now. Not a designed logo, so it's a placeholder until A or C. |
| **C. Commission a designer** | Pay for a logo, then do A. | Best result. Blocks this step until it's delivered, though B could ship meanwhile. |

Whichever option, the **mark** (symbol) and the **name** are handled separately:

- **Mark:** an SVG image. It becomes the favicon, because text can't be read at 16px.
- **Name:** stays real HTML text in Lora next to the mark, not baked into the image. Real text is
  sharp at any zoom, read by screen readers and search engines, and translatable. Text inside an
  `<img src="logo.svg">` also *can't* use the page's web fonts. It would show in a fallback font
  unless converted to outlines.

### 2. Favicon set

The minimal modern set (it covers every current browser without a dozen sizes):

| File | Size | Who uses it |
|---|---|---|
| `favicon.ico` | 32×32 (plus 16×16 inside) | Older browsers, and anything that asks for `/favicon.ico` directly (search results, RSS readers). Must sit at the site root. |
| `favicon.svg` | vector | Modern browser tabs. Sharp at every size and high-DPI screen. |
| `apple-touch-icon.png` | 180×180 | iPhone and iPad home-screen shortcut. Needs a solid background, because iOS fills transparency with black. |

```html
<!-- App.razor -->
<link rel="icon" href="favicon.ico" sizes="32x32" />
<link rel="icon" href="@Assets["favicon.svg"]" type="image/svg+xml" />
<link rel="apple-touch-icon" href="@Assets["apple-touch-icon.png"]" />
<meta name="theme-color" content="#000000" />  <!-- colours the phone browser's address bar to match the header -->
```

**Key concept: favicon caching.** Browsers cache favicons very aggressively, sometimes for days, so
a changed icon often doesn't show up. `@Assets["…"]` adds a content hash to the URL (fingerprinting),
so a new file means a new URL and the browser fetches it right away. `favicon.ico` is the exception:
it must stay at the plain `/favicon.ico` path, because clients request that exact path.

**Light and dark tabs:** the mark sits on a filled, rounded square in `--brand-primary` (#007099),
with the mark itself in white. A filled background stays visible on both light and dark browser
tabs, which a transparent icon wouldn't.

**Generating the PNG and ICO:** a short Python script using Pillow, run locally from the
scratchpad. It's not added to the project, and the outputs are committed. The steps to regenerate
go in the data-flow doc. No new NuGet packages or build steps.

### 3. `BrandLogo` component

```razor
@* Components/Layout/BrandLogo.razor: the mark plus the business name. Used in the nav today,
   and moved into the top navbar by 2.3. *@
<a class="brand-logo" href="">
    <img src="@Assets["logo-mark.svg"]" alt="" width="32" height="32" />  @* decorative: the text says the name *@
    <span>Kinetic Flow RMT</span>
</a>
```

- `alt=""` marks the image as decorative, because the link text already names the brand. A
  screen reader then says "Kinetic Flow RMT, link" once, not twice.
- `width` and `height` attributes stop the layout shifting while the image loads.
- Styles go in `BrandLogo.razor.css`: the mark's size, a gap, and Lora for the name.
- Replaces `<a class="navbar-brand">` in `NavMenu.razor:3`.

## Changes from the plan

- **One SVG instead of two.** The planned separate `logo-mark.svg` isn't needed: the nav sits on
  the black top bar, where the filled brand-blue square reads well, so `BrandLogo` reuses
  `favicon.svg`. That's one less file to keep in sync.
- **Generator script committed** as `tools/make_icons.py`, with `.venv-icons/` gitignored. The plan said
  scratchpad-only, but without the script nobody could regenerate the icons after a colour or font
  change. It's dev-only and not part of the build.
- **`.navbar-brand` rule moved** from `NavMenu.razor.css` to `BrandLogo.razor.css`. CSS isolation
  means NavMenu's rule no longer reaches the `<a>` once a child component renders it.

## Out of scope

- Moving the logo into a top navbar: **2.3**
- A web app manifest (`site.webmanifest`, Android home-screen icons 192/512, installable app). Not
  needed for a brochure site. Could be added in 5.x with SEO and performance work.
- Open Graph or social-share image (`og:image`, the picture shown when the site is shared on
  Facebook and other social sites): **5.x SEO**
