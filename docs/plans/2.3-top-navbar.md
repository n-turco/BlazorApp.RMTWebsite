# 2.3 — Replace the sidebar with a top navbar

**Status:** Done
**Branch:** `feat/2.3-top-navbar`
**Plan reference:** RMT_Website_Plan.docx, task 2.3, plus the deferred step 1 of 2.4 ("merge the
header into the new navbar")

## Goal

Visitors get a familiar top navigation bar: the KF logo on the left, page links on the right, and a
prominent **Book now** button. On phones it collapses into a hamburger menu that works with
mouse, touch, keyboard, and screen readers. The bar stays visible while scrolling, so booking is
always one tap away. Page content gets the full screen width back from the 250px sidebar.

## Current state

- `Components/Layout/MainLayout.razor` is a two-column flex layout: `.sidebar` (NavMenu) on the left,
  and `.page-body` on the right with **two** black bars: NavMenu's own `.top-row` (logo plus
  hamburger) and the header's `.top-row` (full business name, `<p class="site-title">`).
  On phones these stack as two black bars on top of each other.
- `Components/Layout/NavMenu.razor`:
  - The hamburger is an `<input type="checkbox" title="Navigation menu">` styled with CSS (the
    "checkbox hack"). Screen readers announce it as a **checkbox**, not a menu button, and there's
    no `aria-expanded` or `aria-controls`.
  - `.nav-scrollable` has an **inline `onclick`** (`document.querySelector('.navbar-toggler').click()`)
    to close the menu when a link is tapped. Inline event handlers are a code smell, and the roadmap
    asks for this one to be removed. A future Content-Security-Policy (5.x) would also block it.
  - Four of five links use the same generic "list" icon.
- `NavMenu.razor.css` holds five hard-coded `rgba(...)` colours. These are one of the two
  open "Done when" items left from 2.1.
- Active link: `rgba(255,255,255,0.37)` over cyan. It's visible, but it's shown by colour only.
- `NavLink` adds `class="active"` to the current page's link. It doesn't add `aria-current="page"`,
  which is how screen readers announce "current page". (Verify in step 1 in case .NET 10 changed this.)
- Bootstrap 5.3.3's JavaScript is already in `wwwroot/lib/bootstrap/dist/js/` but isn't loaded.
  The only JS on the site is `js/form-submit.js`.
- `BrandLogo` (from #16) is a separate component, so it moves with one tag.
- There's no booking system yet. Online booking is task **4.1**.

## Approach

### 1. New layout

```
Desktop (≥ 992px)
┌──────────────────────────────────────────────────────────────────────────┐
│ [KF] Kinetic Flow RMT        Home  Services  About  Contact  FAQ  [Book now] │  ← sticky, black
├──────────────────────────────────────────────────────────────────────────┤
│                         page content (full width)                         │
├──────────────────────────────────────────────────────────────────────────┤
│                               footer                                      │
└──────────────────────────────────────────────────────────────────────────┘

Phone (< 992px), menu closed / open
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ [KF] Kinetic Flow RMT    [☰] │   │ [KF] Kinetic Flow RMT    [✕] │
├──────────────────────────────┤   │ Home                         │
│ page content                 │   │ Services                     │
                                   │ About                        │
                                   │ Contact                      │
                                   │ FAQ                          │
                                   │ [ Book now (full width) ]    │
                                   └──────────────────────────────┘
```

- `MainLayout.razor` becomes a simple column: `<header>` (NavMenu) → `<main>` → `<SiteFooter />`.
  The `.sidebar`, the second `.top-row`, and the `.site-title` header bar are deleted.
  This is **2.4's step 1**: the brand text lives only in the logo link. The full business name
  still appears in the footer and in every page's `<title>`.
- The links collapse below Bootstrap's `lg` breakpoint (992px). Brand, five links, and the button
  need about 780px, so `md` (768px) would be too tight on a tablet in portrait.
- Bootstrap's `sticky-top` keeps the bar in view while scrolling.
- Icons are dropped. Top navbars with text links are clearer, and the roadmap allows it.

### 2. The hamburger: Bootstrap's collapse JavaScript (decision needed)

| Option | How | Trade-off |
|---|---|---|
| **A. Bootstrap collapse** (recommended) | Load `bootstrap.min.js` (60 KB, 16.5 KB gzipped; the version without Popper, which only dropdowns and tooltips need). Markup uses `data-bs-toggle="collapse"`. | The standard, tested pattern. Bootstrap manages `aria-expanded`, keyboard, and animation. **2.7's FAQ accordion needs the same file**, so it's loaded once for both. |
| B. Small custom script | About 20 lines in `js/nav-toggle.js` that toggle a class and `aria-expanded` | Tiny, but we'd own the accessibility details and edge cases, and 2.7 would still need Bootstrap or more custom JS. |
| C. Keep the checkbox hack, add ARIA | No JS | A checkbox can't properly act as a button. `aria-expanded` on a checkbox is invalid, so screen readers still announce "checkbox". |

**Key concept: static SSR plus enhanced navigation.** The site has no interactive render mode,
so Blazor doesn't run C# in the browser. A click handler has to be plain JavaScript. With
**enhanced navigation**, Blazor fetches the next page and *patches* the current DOM instead of
reloading. Two consequences to verify:

1. Bootstrap's data-attribute API listens on `document`, so it keeps working on patched content.
2. After tapping a link on a phone, the menu should close. Blazor's patch resets the collapse
   `<div>`'s classes to the server's HTML (`collapse` without `show`), which should close it. If it
   doesn't, a few lines listening to Blazor's `enhancedload` event will. This replaces the old
   inline `onclick`.

### 3. Link states (contrast and not relying on colour)

On the black (`--brand-dark`) bar:

| State | Style | Contrast |
|---|---|---|
| Normal | White text | 21:1 |
| Hover / focus | `--brand-accent` cyan text | 11.06:1 |
| **Current page** | Cyan text **plus a 2px underline**, and `aria-current="page"` | 11.06:1. The underline means it doesn't rely on colour alone (WCAG 1.4.1). |
| Keyboard focus | The existing focus ring (`app.css`), plus a visible outline on dark | ≥ 3:1 against black |

`aria-current="page"`: if `NavLink` doesn't add it, wrap `NavLink` in a tiny `NavItem` component, or
add `aria-current` from the matching state. Decide after checking what .NET 10 renders.

The Book now button uses cyan with black text (11.06:1), the brightest thing on the bar. On phones
it's full width at the bottom of the open menu.

**Sticky header and keyboard focus (WCAG 2.4.11):** a sticky bar can cover the element a keyboard
user has just tabbed to, near the top of the screen. Add `scroll-padding-top` (about the bar's
height) on `html` in `app.css`, so the browser scrolls focused elements and `#anchors` clear of it.

### 4. CSS clean-up

- `NavMenu.razor.css` is rewritten for the navbar. All `rgba(...)` colours are replaced with brand
  tokens, which closes 2.1's "no hard-coded colours" item for NavMenu.
- `MainLayout.razor.css`: delete `.sidebar`, `.top-row`, `.site-title`, and the ≥641px two-column
  rules. Keep `#blazor-error-ui`.
- `BrandLogo.razor.css` stays the same.

## Changes from the plan

- **`aria-current` came for free:** .NET 10's `NavLink` already renders `aria-current="page"` on the
  active link (checked in step 1), so no wrapper component was needed.
- **No `enhancedload` fallback needed:** enhanced navigation's DOM patch closes the menu by itself.
- **Skip link href is computed:** `<base href="/">` would send `#main-content` to the home page, so
  `MainLayout` builds `currentPath#main-content`, with `data-enhance-nav="false"` for a native jump.
- **Dead CSS removed:** the `#blazor-error-ui` rules (no matching element since the static SSR template
  dropped it), which held one more hard-coded `rgba()`.
- **Toggler mouse-focus glow removed:** Bootstrap styles `:focus`, which left a thick white ring
  after a tap. Keyboard users keep the `:focus-visible` cyan outline.
- **FocusOnNavigate:** the template's `<FocusOnNavigate Selector="h1">` (Routes.razor) moves focus to
  the `<h1>` on every load. It's kept, because it's the right behaviour after following a link.
