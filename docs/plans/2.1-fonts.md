# 2.1 — Brand fonts and type scale

**Status:** In progress (2 manual browser checks left)
**Branch:** `feat/2.1-fonts`
**Plan reference:** RMT_Website_Plan.docx, task 2.1 (step: "Choose one heading font and one body font
and set a consistent type scale")

## Goal

Every page uses the same two brand fonts, one for headings and one for body text, and heading
sizes follow one consistent scale. The site looks the same on every visitor's device, not just
whatever fonts their system happens to have. Pages load as fast as they do now, and no visitor
data goes to a third party.

## Current state

- `BlazorApp.RMTWebsite/wwwroot/app.css:18` sets
  `font-family: 'Helvetica Neue', Helvetica, Arial, sans-serif` on `html, body`. That is a
  *system font stack*, so Mac visitors see Helvetica Neue and Windows visitors see Arial.
- No custom fonts are loaded. `Components/App.razor:9-12` loads Bootstrap, Bootstrap Icons,
  `app.css`, and the scoped styles bundle.
- Bootstrap's own font variables (`--bs-body-font-family`, `--bs-font-sans-serif`) are not
  overridden, so any Bootstrap component that reads them still uses Bootstrap's default stack.
- Heading sizes come from Bootstrap's defaults plus a few hard-coded sizes in scoped CSS:
  `NavMenu.razor.css:25` (1.3rem), `:52` (0.9rem), `SiteFooter.razor.css:10` (1.1rem),
  `:35` (1.5rem), `:40` (0.85rem). These are component-specific and can stay as they are.
- The brand palette added in #12 already follows the pattern this plan copies: define a value once
  as a custom property in `:root`, then point Bootstrap's variables at it (`app.css:1-16`).

**Noticed but out of scope:** pages use `<h3>` as their main heading, the only `<h1>` is the site
name in `MainLayout.razor:10`, and `ContactUs.razor:20,26,32` puts `<h5>` inside `<label>`. That is
a heading-structure and accessibility fix, not a font change. It belongs with the inline-style
cleanup or the page redesigns (2.2+), so this PR doesn't touch it.

## Approach

### 1. Font choice

| Role | Font | Why |
|---|---|---|
| Headings | **Lora** (serif) | Soft, rounded serif that reads calm and professional, a common fit for wellness and health brands. Variable font, so one file covers weights 400–700. |
| Body | **Inter** (sans-serif) | Built for screens and very readable at small sizes and on phones. Also a variable font. |

Both are free under the SIL Open Font License (OFL), which allows self-hosting and bundling as long
as the license file ships with the fonts.

Alternatives considered: Playfair Display (higher contrast and more "luxury spa", harder to read at
small heading sizes) and Nunito Sans for body (friendlier, but less crisp than Inter on Windows).

### 2. Self-host instead of linking Google Fonts

There are two ways to load the fonts:

- **Google Fonts `<link>`:** one line of HTML, but every page view makes the visitor's browser
  contact Google's servers. That sends Google the visitor's IP address, which matters for a health
  business and is the reason some European courts have ruled against it. It also adds a connection
  to a second domain before text can render.
- **Self-host (chosen):** download the `.woff2` files into `wwwroot/fonts/` and declare them with
  `@font-face` in `app.css`. The fonts come from our own server, get the same caching as our other
  static assets, keep working if Google is unreachable, and send no visitor data anywhere.

This is a significant, lasting choice, so it gets an ADR: `docs/decisions/0003-self-hosted-fonts.md`.

Font files come from the Fontsource project (`@fontsource-variable/lora` and
`@fontsource-variable/inter` on npm), which repackages the Google Fonts files. We take only the
**Latin** subset of each (about 50 KB per font). The site is English-only, so we skip the Cyrillic,
Greek, and Vietnamese files.

### 3. How the CSS fits together

Same pattern as the color palette: tokens in `:root`, Bootstrap pointed at the tokens.

```css
/* Self-hosted brand fonts (plan 2.1, ADR 0003). */
@font-face {
    font-family: 'Lora';
    src: url('fonts/lora-latin-wght-normal.woff2') format('woff2');
    font-weight: 400 700;     /* variable font: one file, a range of weights */
    font-style: normal;
    font-display: swap;       /* show fallback text immediately, swap when the font arrives */
}

:root {
    --font-heading: 'Lora', Georgia, 'Times New Roman', serif;
    --font-body: 'Inter', system-ui, -apple-system, 'Segoe UI', Arial, sans-serif;

    /* Bootstrap reads these for body text and most components. */
    --bs-font-sans-serif: var(--font-body);
    --bs-body-font-family: var(--font-body);
}

/* Bootstrap has no CSS variable for heading fonts (only a Sass variable), so set it directly. */
h1, h2, h3, h4, h5, h6,
.h1, .h2, .h3, .h4, .h5, .h6,
.display-1, .display-2, .display-3, .display-4, .display-5, .display-6 {
    font-family: var(--font-heading);
}
```

**Key concepts for this change:**

- **`font-display: swap`.** Without it, some browsers hide text for up to 3 seconds while the font
  downloads, which leaves a blank page on slow mobile connections. `swap` shows the fallback font
  right away and switches when the font arrives.
- **Fallback stacks.** If a font file fails to load, the browser moves down the list. Georgia and
  `system-ui` are close in shape to Lora and Inter, so the page still looks intentional.
- **Preloading.** The browser only discovers a font after it has downloaded and parsed the CSS.
  A `<link rel="preload" as="font" crossorigin>` in `App.razor` starts the body-font download
  earlier. We preload only Inter, because it's on every line of every page. Preloading both would
  compete with more important downloads. (`crossorigin` is required on font preloads even for
  same-origin files, or the browser downloads the font twice.)

### 4. Type scale

A **modular scale** multiplies each heading size by the same ratio, so sizes look related instead
of picked at random. We use a ratio of **1.25** (a "major third") on a 1rem (16px) base:

| Token | Size | Used by |
|---|---|---|
| `--fs-h1` | `clamp(2rem, 1.6rem + 1.6vw, 2.441rem)` | `h1`, `.h1` |
| `--fs-h2` | `clamp(1.65rem, 1.4rem + 1vw, 1.953rem)` | `h2`, `.h2` |
| `--fs-h3` | `1.563rem` | `h3`, `.h3` |
| `--fs-h4` | `1.25rem` | `h4`, `.h4` |
| `--fs-h5` | `1.125rem` | `h5`, `.h5` |
| `--fs-h6` | `1rem` | `h6`, `.h6` |
| body | `1rem` (Bootstrap default, unchanged) | everything else |

`clamp(min, preferred, max)` lets h1 and h2 shrink on a 375px phone and grow on desktop without
media queries. It replaces Bootstrap's built-in responsive font sizing (RFS) for those two headings.
`.display-*` classes keep Bootstrap's sizes and only take the heading font.

We also set a heading `line-height` of 1.25 (Bootstrap uses 1.2, which is tight for a serif) and
leave body line-height at Bootstrap's 1.5. That spacing helps meet WCAG 1.4.12 (text spacing).

## Steps

1. Write ADR `docs/decisions/0003-self-hosted-fonts.md` covering self-hosting vs Google Fonts.
2. Download the Latin variable `.woff2` files for Lora and Inter from Fontsource into
   `BlazorApp.RMTWebsite/wwwroot/fonts/`, along with `OFL.txt` (license) for each font.
3. In `wwwroot/app.css`, add the `@font-face` rules, the `--font-*` and `--fs-*` tokens, map the
   Bootstrap variables, and add the heading rules. Remove the old `font-family` on `html, body`
   (`app.css:17-19`), which the Bootstrap variable now covers. Comment each block.
4. In `Components/App.razor`, add a preload for the Inter file before the stylesheets.
5. Add a test (see Verification) that every `url(...)` in an `@font-face` rule in `app.css` points
   to a file that exists in `wwwroot`. This catches a typo'd filename, which otherwise fails
   *silently*: the fallback font shows and nothing errors.
6. Write `Visual_dataflow_features/2.1-fonts.md`, a flow chart of how the browser finds,
   downloads, and applies the fonts (HTML → preload → CSS → `@font-face` → swap).
7. Run the site and check every page at 375px and desktop widths.
