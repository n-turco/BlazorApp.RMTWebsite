# 2.1 — Remove inline styles

**Status:** Done
**Branch:** `chore/2.1-inline-styles`
**Plan reference:** RMT_Website_Plan.docx, task 2.1 (step: "Remove inline `style=` attributes across
pages and use the shared classes instead")

## Goal

No `style=""` attributes remain in the site's markup. Every style lives in `app.css`, a component's
scoped `.razor.css`, or a Bootstrap class, so a style can be found, reused, and changed in one
place. The pages look the same as today, except the About photo, which stops running off the
screen on phones.

## Current state

Five inline styles are left, in three pages. None of those pages has a `.razor.css` file yet.

| # | Where | Inline style | What it does |
|---|---|---|---|
| 1 | `Pages/Home.razor:6` | `width:100%; height:600px; overflow:hidden` on a `<div>` | Fixed-height frame for the hero image |
| 2 | `Pages/Home.razor:7` | `width:100%; height:100%; object-fit:cover` on the `<img>` | Image fills the frame and is cropped, not stretched |
| 3 | `Pages/About.razor:10` | `height:500px; margin-left:35%` on the photo | Fixed size; the margin is a hack to roughly centre it |
| 4 | `Pages/ContactUs.razor:34` | `resize:none` on the message `<InputTextArea>` | Stops the visitor resizing the box |
| 5 | `Pages/ContactUs.razor:38` | `border-radius:10px` on the Submit button | Rounder corners than Bootstrap's default |

Other things found:

- **#3 is the bug seen in #14.** The photo is 564×838px, so at 500px tall it's 336px wide. Add the
  35% left margin and it runs off a 375px screen. `margin-left:35%` also only looks centred at
  one particular screen width.
- `About.razor:4` has a stale comment, `<!--MOVE THE INLINE CSS FOR H3 HEADERS INTO CSS FILE-->`.
  It refers to an `<h3>` that #14 already turned into an `<h1>`, and HTML comments are sent to
  every visitor's browser. Remove it.
- Home's `<img>` has Bootstrap's `img-fluid` (`max-width:100%; height:auto`), which fights the inline
  `height:100%`. The inline style only wins because inline styles beat classes.

### Overlap with later tasks

All three pages get redesigned later: Home in 2.2, About in 2.6, and the contact form in 3.1. This
PR deliberately **moves styles without redesigning anything**. The redesigns then start from clean
markup, and this PR stays small and easy to review. The one exception is the About photo, because
it's broken on phones today.

## Approach

### Key concept: Blazor CSS isolation and `::deep`

A `Page.razor.css` file only styles that page. At build time, Blazor adds a unique attribute such as
`b-x7k2p9` to every **HTML element written directly in `Page.razor`**, and rewrites each selector in
the `.razor.css` to require it (`.hero` becomes `.hero[b-x7k2p9]`).

The catch: `<InputTextArea>` is a **component**, not an HTML element. The `<textarea>` it produces is
rendered by `InputTextArea`, not by `ContactUs.razor`, so it doesn't get ContactUs's attribute, and
a plain `.message-input { … }` rule in `ContactUs.razor.css` would silently never match. The fix
is `::deep`, which means "a descendant of my element, even one rendered by a child component":

```css
/* ContactUs.razor.css: .message-field is a plain <div> in ContactUs.razor, so it gets the
   scope attribute. ::deep then reaches the <textarea> that InputTextArea renders inside it. */
.message-field ::deep textarea {
    resize: vertical;
}
```

`NavMenu.razor.css` already uses `::deep` for `<NavLink>` in the same way.

### Each style

| # | Moves to | How |
|---|---|---|
| 1, 2 | New `Home.razor.css` | `.hero` (frame) and `.hero-image` (`object-fit: cover`) classes. Drop `img-fluid`, which conflicts. The 600px height stays for now, because 2.2 replaces it with a responsive height. |
| 3 | New `About.razor.css` + Bootstrap | `d-block mx-auto` centres it properly at any width. A scoped `.profile-photo` rule uses `max-height: 500px; max-width: 100%; height: auto; width: auto`, so the photo is 500px tall on desktop, shrinks to fit on phones, and keeps its shape. |
| 4 | New `ContactUs.razor.css` | Wrap the field in `<div class="message-field">` (the existing `mt-1 w-75` div gets the class) and use `::deep textarea`. **Small change:** `resize: vertical` instead of `none`, so visitors can make the box taller but not wider. |
| 5 | Bootstrap class | `rounded-3` (0.5rem = 8px) instead of 10px. It's a 2px difference that's hard to see, and it's a shared class instead of a one-off value. |

**Why `resize: vertical` instead of `none`:** a visitor writing a long message, or using a large
text size, can drag the box taller to see what they've written. Stopping sideways resizing still
protects the layout. This matches the roadmap's "use the shared classes instead" spirit and
WCAG's goal of letting users adapt content. If you'd rather keep `none`, it's a one-word change.
