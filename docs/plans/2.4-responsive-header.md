# 2.4 — Make the header responsive

**Status:** In progress
**Branch:** `fix/2.4-responsive-header` (branch from `master` after #13, the fonts PR, merges)
**Plan reference:** RMT_Website_Plan.docx, task 2.4

## Goal

The header never overflows or clips at any phone width, down to 320px. Each page has exactly one
`<h1>` that names that page, so screen-reader users and search engines can tell the pages apart.

## Current state

- `Components/Layout/MainLayout.razor:10` renders the full business name as an `<h1>` inside
  `.top-row`. That same `<h1>` appears on every page.
- `Components/Layout/MainLayout.razor.css:19-26` gives `.top-row` a fixed `height: 3.6rem`. At 375px
  the name wraps to two lines (~4.5rem tall), so it spills out of the black bar and over the page.
  This also happens on `master` with the old font, so it predates #13.
- On phones, the layout stacks `NavMenu` (black bar with "Kinetic Flow RMT" and the hamburger) above
  this header, so the brand name already shows twice on mobile.
- Page titles are `<h3>`, not `<h1>`: `Services.razor:3`, `About.razor:5` (with `display-3`),
  `ContactUs.razor:11` (with an inline `style="text-align:center"`), `FAQ.razor:5`,
  `NotFound.razor:4`. `Home.razor` has no heading at all. `Error.razor:6` already has its own `<h1>`,
  so today the Error page has **two**.

### How this relates to 2.3

The roadmap's step 1 for 2.4 is "merge the header into the new navbar from 2.3". Task 2.3 (replace
the sidebar with a top navbar) hasn't started yet. Steps 2 and 3, per-page `<h1>` and removing the
fixed height, don't depend on 2.3. They fix the visible bug now, and the work carries over: when 2.3
lands, the header bar is deleted and the per-page `<h1>`s stay. So this PR does steps 2 and 3, and
**step 1 moves into 2.3's plan**.

## Approach

### 1. The header becomes a brand line, not a heading

A heading should describe *the content of this page*. The business name is the same on every page,
so it's branding. Change it from `<h1>` to `<p class="site-title">`. It stays visible and styled the
same, but it no longer competes with the page's own `<h1>`.

### 2. Let the bar grow instead of overflowing

Replace `height: 3.6rem` with `min-height: 3.6rem` plus vertical padding. `min-height` keeps the bar
the same size on desktop, but lets it grow when the text wraps, so it can't overflow.

Give `.site-title` its own fluid size with `clamp()`, like the h1/h2 tokens in #13, so it fits on
one line on most desktops and at most two lines on a 320px phone:

```css
.site-title {
    font-family: var(--font-heading);      /* still looks like the brand */
    font-size: clamp(1.25rem, 0.9rem + 1.8vw, 2.25rem);
    line-height: var(--lh-heading);
    margin: 0;                             /* <p> has a bottom margin by default */
    text-align: center;
}
```

*Alternative considered:* hide the header bar below 641px, because the NavMenu bar already shows
"Kinetic Flow RMT" there. That saves vertical space on phones, but 2.3 replaces both bars anyway,
and hiding content is a bigger design decision than this fix needs. Rejected for now.

### 3. One `<h1>` per page

| Page | Today | After |
|---|---|---|
| Home | no heading | `<h1 class="visually-hidden">Kinetic Flow Registered Massage Therapy</h1>`. It's read by screen readers but not shown, because the page is only an image until 2.2 adds a visible hero headline. |
| Services | `<h3>Services</h3>` | `<h1>Services</h1>` |
| About | `<h3 class="text-center display-3">` | `<h1 class="text-center display-3">`: looks the same, because `display-3` sets the size |
| Contact | `<h3 style="text-align:center">` | `<h1 class="text-center">`. This also removes one of the 6 leftover inline styles. |
| FAQ | `<h3>FAQ</h3>` | `<h1>FAQ</h1>` |
| Not Found | `<h3>Not Found</h3>` | `<h1>Not Found</h1>` |
| Error | `<h1>` already | no change. It now has only one `<h1>`. |

Visible change: page titles get bigger, going from the h3 size (1.563rem) to the h1 size (2–2.44rem)
in the #13 type scale. That's intended, because the main title of a page should be its largest text.

- [ ] Screen reader or Accessibility Insights headings list. Not checked yet; needs a manual check.
- [x] No secrets in the diff

**Testing lesson:** headless Edge on Windows won't make a window narrower than about 500px, so
`--window-size=320,...` screenshots are really crops of a wider page. Use fixed-width iframes or
DevTools device mode for phone widths. The 375px screenshots in #13 had this problem too, so its
"no new overflow at 375px" claim was only really checked at 1280px.

**Found, out of scope:** at 375px the About photo runs off the right edge
(`About.razor:10`, inline `height:500px; margin-left:35%`). That's the inline-style cleanup (2.1)
or the mobile pass (3.4).
