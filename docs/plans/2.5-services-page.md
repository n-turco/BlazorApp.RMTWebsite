# 2.5 — Redesign the Services page

**Status:** Approved 2026-10-06 (see Decisions).
**Branch:** `feat/2.5-services-page` (from `master` after #20 merges, because it builds on `IServiceCatalog`)
**Plan reference:** RMT_Website_Plan.docx, task 2.5 (Priority: High, Effort: M), plus the PageHeader step of 2.8

## Goal

A visitor can see what each treatment is, who it helps, what each length costs, and book it from
the same card, comfortably on a phone. The roadmap's "Done when": *each treatment is described and
bookable from the page*, and *the page reads well on a phone without horizontal scrolling*.

## Current state (after #20)

- `Components/Pages/Services.razor`:
  - `<h1>Services</h1>`, then `<hr/><br/>` spacing hacks (2.8 wants these gone).
  - A stale `<!--NEED TO ADD A BUTTON TO EACH OPTION FOR BOOKING-->` comment. HTML comments are sent to
    every visitor's browser.
  - A 3-column table from `IServiceCatalog` that repeats "Swedish Massage" on every row. There's no
    `table-responsive` wrapper, no description, and no booking button.
- `Models/ServiceOffering.cs` has only `Name` and `Options` (minutes and price), so there's nowhere to put a
  description or "who it helps".
- **Decided already:** Swedish massage is the only treatment, and the price list doesn't change (2026-10-05).
  That answers the roadmap's "add other treatments or confirm only Swedish" step.
- Not stated anywhere on the site: whether prices include **HST**, or whether **receipts for insurance** are provided.
- `ServicesPageTests` (from #20) pins today's table rows. This redesign changes the page on purpose,
  so that test gets rewritten for the new layout. That's expected, not a regression.

## Approach

### Page layout

```
┌ PageHeader ───────────────────────────────────────────────┐
│ Services and rates                       (h1)              │
│ Registered massage therapy in Guelph, Ontario (subtitle)   │
├───────────────────────────────────────────────────────────┤
│ ┌ card: <article aria-labelledby> ──────────────────────┐ │
│ │ Swedish Massage                         (h2)          │ │
│ │ 2–3 sentence description                              │ │
│ │ Helps with:  • …  • …  • …            (list)          │ │   phone: everything stacked
│ │ ┌ Prices (table, caption) ┐                           │ │   ≥768px: description left,
│ │ │ 30 min   $90.00         │                           │ │           price table right
│ │ │ 45 min   $110.00   …    │                           │ │
│ │ └─────────────────────────┘                           │ │
│ │ [Book this treatment]  → /contact (until 4.1)         │ │
│ └───────────────────────────────────────────────────────┘ │
│ Pricing note: HST and insurance receipts   (from Q2/Q3)   │
├───────────────────────────────────────────────────────────┤
│ <CallToAction Heading="Not sure which length?" …/>         │  shared component from #20
└───────────────────────────────────────────────────────────┘
```

- **One page, one card per treatment** (not per length), rendered with `@foreach` over `IServiceCatalog`.
  Swedish is the only treatment, so the page shows a single card, and all five lengths are rows in that
  card's price table. A new treatment added to the catalog later gets its own card with no markup changes.
- **Prices as a small table inside the card:** two columns (Length, Price) with a visually hidden
  `<caption>` ("Swedish Massage prices"). A table is the right element for paired data. Screen readers
  announce "60 minutes, $130.00" row by row. Wrapped in `table-responsive` as the roadmap asks, though
  two columns never need to scroll.
- **"Book this treatment"** uses the shared `.btn-accent`, but on a white card cyan is a weak edge (see the
  key concept below). So the card uses `.btn-primary` (white on brand blue, 5.56:1). The accent stays
  for dark backgrounds.

### Key concept: text contrast vs. component contrast

WCAG has two separate contrast rules:
- **1.4.3 Text, 4.5:1:** the button's *label* against the button's fill.
- **1.4.11 Non-text, 3:1:** the button's *shape* against the background around it, where that shape is
  what tells you it's a button.

The cyan `.btn-accent` passes 1.4.3 everywhere (black on cyan, 11.06:1). But cyan against a white card
is only about 1.9:1, so on white the button's edge is faint. On black (navbar, hero, CTA) cyan
against black is 11:1. That's why the accent stays for dark bands, and white cards use `.btn-primary`
(brand blue against white, 5.56:1).

### Data: extend the model, not the markup

```csharp
public record ServiceOffering(
    string Name,
    string Description,                 // 2–3 sentences
    IReadOnlyList<string> HelpsWith,    // short bullet points
    IReadOnlyList<ServiceOption> Options);
```

- `ServiceCatalog` gets the approved Swedish description and list (Q1).
- The Home preview from #20 keeps working unchanged. It only reads `Name`, the minutes, and the price.
- The roadmap's "load from a model (see 4.3)" is met. 4.3 later moves this data to configuration.

### PageHeader component (2.8, step 1)

```razor
<PageHeader Title="Services and rates" Subtitle="Registered massage therapy in Guelph, Ontario" />
```

- Renders the page's single `<h1>`, an optional subtitle, and a consistent bottom divider/spacing in
  CSS. That replaces the `<hr/><br/>` hacks.
- Used **only on Services** in this PR. Rolling it out to About, Contact, FAQ, and Not Found is the rest of
  2.8 (a small follow-up), so this PR stays focused.
- The browser tab title also becomes "Services and rates". `PageRoutingTests` is updated to match.

### Pricing note (depends on Q2/Q3)

One short line under the cards, using only the confirmed facts:
*"Prices are plus HST. Official receipts are provided for extended health insurance claims."*

   > on areas of tension, and each session is shaped by your health history and goals.*

   > **Helps with:** muscle tension and stiffness · stress and trouble relaxing · recovery from training
   > and everyday aches · ongoing (chronic) muscle pain, as part of a treatment plan
3. **HST:** prices are **plus HST**.
4. **Insurance receipts:** yes, official receipts are provided for extended health insurance claims.
5. **Title:** the heading and browser tab become **"Services and rates"**. The nav link stays "Services".
6. **PageHeader:** included in this PR, used on Services only.
