# 2.2 — Home page hero

Plan task 2.2, PR 1. These diagrams show how the hero is layered, why the photo loads first, how
the overlay guarantees readable text, and how the "Book" buttons share one style. They render on
GitHub and in VS Code's Markdown preview (Mermaid). PR 2 (sections below the hero) will add to this file.

## 1. What the first screen answers

| Visitor's question | Answered by | Element |
|---|---|---|
| What is this? | "Therapeutic massage for recovery, pain relief, and performance" | `<h1>` (the page's only one) |
| Where is it? | "Registered massage therapy in Guelph, Ontario" | subheading |
| How do I book? | **Book an appointment** → `/contact` (until 4.1), **View services** → `/services` | two buttons |

Checked in Edge: all three are visible without scrolling at 320, 375, 768, and 1440px.

## 2. How the hero is layered

```mermaid
flowchart TB
    subgraph Hero["section.hero (position: relative, min-height 60vh / 70vh)"]
        direction TB
        T["3 · .hero-content (z-index 1)<br/>h1 · subheading · buttons"]
        O["2 · .hero::after (overlay)<br/>background: var(--hero-overlay) = black at 60%"]
        I["1 · img.hero-image (object-fit: cover)<br/>photo fills and is cropped, never stretched"]
        B["0 · background-color: --brand-dark<br/>(shown while the photo loads)"]
        T --- O --- I --- B
    end
```

`min-height` instead of `height`: if the text needs more room (a 320px phone, or 200% zoom), the
hero grows instead of cutting the text off. The negative margins cancel `<main>`'s padding so the
photo runs edge to edge.

## 3. Why an `<img>`, not a CSS background

```mermaid
sequenceDiagram
    participant B as Browser
    participant S as Server

    B->>S: GET /
    S-->>B: HTML
    Note over B: Preload scanner reads the HTML and finds<br/>&lt;img src="images/hero-massage.….jpg" fetchpriority="high"&gt;
    B->>S: GET hero image (high priority, starts immediately)
    B->>S: GET CSS files
    Note over B: With a CSS background-image, the browser<br/>would only learn about the photo HERE,<br/>after downloading and parsing the CSS
    S-->>B: photo + CSS
    Note over B: Largest Contentful Paint = hero photo
```

The hero photo is the biggest thing on the first screen, so it's what Google measures as
**Largest Contentful Paint (LCP)**. Starting its download early makes the page *feel* faster, and LCP
also feeds into search ranking. `width="1920" height="1282"` lets the browser reserve the space
before the photo arrives, so nothing jumps.

## 4. The overlay maths

White text has to reach 4.5:1 contrast over *every* part of the photo, including its brightest pixel.

| Overlay (black) | Pure-white pixel becomes | White text on it |
|---|---|---|
| 0.50 | `#808080` | 3.95:1 ✗ |
| 0.55 | `#737373` | 4.74:1 (just passes) |
| **0.60 (used)** | `#666666` | **5.74:1** ✓ |

Because it holds for a pure-white pixel, it holds for any photo. A future photo swap can't break
contrast as long as `--hero-overlay` stays at 0.6 or above.

## 5. One style for every "Book" button

```mermaid
flowchart LR
    A["app.css<br/>.btn-accent<br/>black on cyan, white on hover"] --> N["NavMenu: Book now<br/>class=&quot;btn btn-accent book-button&quot;<br/>(book-button = layout only)"]
    A --> H["Home hero: Book an appointment<br/>class=&quot;btn btn-lg btn-accent&quot;"]
    A -. "PR 2" .-> C["CallToAction component"]
```

The colours used to live in `NavMenu.razor.css`, where scoped CSS can't reach other components. Moving
them to a global class means every booking button matches, and a brand colour change happens in one place.

## 8. One source of truth for prices

```mermaid
flowchart LR
    SC["ServiceCatalog<br/>(in memory)<br/>Swedish Massage: 30/90, 45/110,<br/>60/130, 75/145, 90/160"] -->|"implements"| I["IServiceCatalog"]
    P["Program.cs<br/>AddSingleton&lt;IServiceCatalog, ServiceCatalog&gt;"] -.->|"registers"| I
    I -->|"@inject"| S["Services.razor<br/>table: every option<br/>option.FormattedPrice"]
    I -->|"@inject"| H["Home.razor<br/>preview: from @offering.FormattedStartingPrice<br/>MinMinutes to MaxMinutes"]
    M["ServiceOption.FormatPrice()<br/>CultureInfo en-CA → $90.00"] --- S
    M --- H
```

- **Before:** the prices were typed into the Services table, so a Home preview would have needed a second copy.
- **After:** both pages ask `IServiceCatalog`. Change a price in `ServiceCatalog.cs` and both pages update.
  `ServiceCatalogTests` pins today's prices, so a change can't happen by accident.
- **Later (4.3):** a config- or file-backed `IServiceCatalog` can replace the in-memory one. No page changes,
  because pages depend on the *interface*, not the class (dependency inversion).

## 9. Why prices are formatted with a fixed culture

```mermaid
flowchart TD
    V["90m.ToString(&quot;C&quot;)"] --> Q{"Server's CurrentCulture?"}
    Q -->|en-CA| A["$90.00"]
    Q -->|fr-FR| B["90,00 €"]
    Q -->|de-DE| C["90,00 €"]
    F["ServiceOption.FormatPrice(90m)<br/>ToString(&quot;C&quot;, en-CA)"] --> D["$90.00 everywhere"]
```

Cloud hosts don't promise a culture. `FormattedPrice_AnyServerCulture_IsCanadianDollars` runs under
`fr-FR`, `en-US`, and `de-DE` and always expects `$90.00`.

## 10. Eager vs. lazy images

| Image | Where | Attribute | Why |
|---|---|---|---|
| Hero photo | First screen | `fetchpriority="high"` | It's the Largest Contentful Paint: start it first |
| Nick's photo | Below the fold | `loading="lazy"` | Fetched only as the visitor scrolls near it, which saves data on phones |

Browsers start "lazy" images a little before they scroll into view (a screen or two ahead), so the
photo is usually ready by the time it's seen. In the Edge check it waited at 320px, where the page
is tallest, and was prefetched at wider widths.

## 11. The shared CallToAction component

```razor
<CallToAction Heading="Ready to book?" Text="Appointments in Guelph, Ontario. …" />
```

| Parameter | Default | Notes |
|---|---|---|
| `Heading` | (required, `EditorRequired`) | Rendered as the section's `h2` |
| `Text` | none | Optional supporting line |
| `ButtonText` | "Book an appointment" | |
| `Href` | "contact" | Becomes the booking page in 4.1 |

The button uses the shared `.btn-accent` class, so it matches the navbar and the hero. Each instance
generates its own heading id, so two calls to action on one page never clash. The component doesn't
know about page padding, so the page that uses it decides whether it's full-width (Home wraps it in `.full-bleed`).
